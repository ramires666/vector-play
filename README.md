# VectorPlay

Мобильный калькулятор векторной алгебры слов на нескольких моделях Word2Vec/GloVe.

## Возможности
- Три модели: 🇬🇧 **English Classic** (Google News Word2Vec 300D, 3M слов), 🇬🇧 **English Modern** (Stanford GloVe 2024 300D, 1.2M слов), 🇷🇺 **Русский** (RusVectōrēs 300D, 249k слов).
- Переключатель языка и модели в шапке: по умолчанию английский интерфейс и английская модель, можно выбрать любую модель вручную.
- Сложение и вычитание смысловых векторов слов и выражений.
- Поиск ближайшего результата по полному словарю выбранной модели.
- Общая коллекция **«Мемориз»** в SQLite с отдельным списком для каждой модели.
- Сохранение результата кнопкой **«В мемориз»**, просмотр коллекции по `/memories` (фильтр по модели).
- Автоматическое обновление общей ленты раз в секунду.
- Адаптивный мобильный интерфейс, галочка скрытия готовых примеров.

## Модели

| id | Модель | Словарь | Загрузка | RAM в памяти |
|---|---|---|---|---|
| `en-google` | 🇬🇧 English Classic — Google News Word2Vec 300D | ~3M | 1.6 ГБ | ~3.8 ГБ |
| `en-glove` | 🇬🇧 English Modern — Stanford GloVe 2024 300D | ~1.29M | 1.6 ГБ | ~1.6 ГБ |
| `ru-rusvectores` | 🇷🇺 Русский — RusVectōrēs Word2Vec 300D | ~249k | 0.6 ГБ | ~0.3 ГБ |

Модель по умолчанию задаётся `VECTOR_CALC_DEFAULT_MODEL` (сейчас `en-google`).

### Как выключить лишние модели

Полный реестр моделей всегда остаётся в коде (`MODELS` в `word2vec_engine.py`), а конкретный запуск включает только нужные:

```yaml
      VECTOR_CALC_ENABLED_MODELS: "ru-rusvectores"   # только русская
      # "en-google,ru-rusvectores" — русская и Google News
```

Что это даёт: выключенные модели не загружаются в память, не предзагружаются при старте, не скачиваются entrypoint'ом, не появляются в списке моделей и в переключателе языков (если доступен один язык, кнопки EN/RU скрываются), а их записи не мелькают в общей ленте «Мемориз» (при фильтре «все модели» показываются только включённые). Опечатка в id — падение на старте с понятным сообщением, чтобы лишнее не открылось молча. Скачать выключенную модель всё же можно явно: `python download_model.py en-google`.

### Память и переключение моделей

Загруженные модели живут в LRU-кэше с бюджетом памяти, поэтому два посетителя на русской и английской моделях не перезагружают вектора друг за другом:

- бюджет по умолчанию считается автоматически: доступная память (cgroup-лимит в Docker, `/proc/meminfo`, а на Windows — системный API) минус 1 ГБ запаса; переопределяется `VECTOR_CALC_MODEL_CACHE_MB` (0 — без предела);
- пока модели влезают в бюджет, они остаются в памяти вместе: 🇷🇺 + GloVe ≈ 2.2 ГБ, 🇷🇺 + Google News ≈ 4.4 ГБ, Google News + GloVe ≈ 5.7 ГБ, все три ≈ 6.0 ГБ (это RSS процесса целиком вместе с Python; проверено на реальных моделях);
- если не влезают, вытесняется модель, простаивающая дольше `VECTOR_CALC_MODEL_IDLE_EVICTION_S` (по умолчанию 180 с). Недавно использованную модель не вытесняют: запрос получит 503 с понятным объяснением вместо бесконечной перезагрузки;
- бюджет, список резидентных моделей и фактический размер каждой видны в `GET /api/models` и `GET /api/status`;
- при старте сервер пишет в лог строку вида `Кэш моделей: бюджет 15682 МБ (авто (16706 МБ доступно))`, а если бюджета не хватает на модель по умолчанию плюс вторую — предупреждение.

Практическое правило: серверу с 4 ГБ памяти лучше оставить `VECTOR_CALC_DEFAULT_MODEL: "en-glove"` (пара «англ+рус» ≈ 2.1 ГБ), а Google News включать при 6+ ГБ.

```bash
python download_model.py                  # модель по умолчанию
python download_model.py ru-rusvectores   # конкретная модель
python download_model.py --all            # все три (~3.9 ГБ)
```

Закачка продолжается с места обрыва (HTTP Range), проверяется после скачивания, а повторный запуск уже скачанное пропускает.

## Установка

Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe download_model.py
.\.venv\Scripts\python.exe server.py
```

Linux/macOS — достаточно одного скрипта, он создаст `.venv`, поставит зависимости, скачает модель при первом запуске и стартует сервер:

```bash
chmod +x start.sh
./start.sh
```

Вручную на Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_model.py
.venv/bin/python server.py
```

Откройте `http://localhost:58765/`. Для устройств LAN используйте `http://<IP_сервера>:58765/`.

На Windows для входящих подключений должен быть разрешён TCP 58765. Рекомендуется ограничить правило своими LAN-подсетями. Сервер по умолчанию слушает `0.0.0.0:58765`, поэтому не пробрасывайте этот порт в интернет без HTTPS, авторизации и лимитов запросов.

На Linux при необходимости откройте порт, например: `sudo ufw allow 58765/tcp`.

Переменные окружения: `VECTOR_CALC_HOST`, `VECTOR_CALC_PORT` и другие — см. таблицу в разделе «Безопасность».

## Docker

Контейнер собирается на сервере с Docker Engine 20.10+ и Compose v2 (команда `docker compose`). Папка проекта монтируется в контейнер целиком, поэтому база и модель живут на хосте.

```bash
docker compose up -d --build
```

- По умолчанию порт опубликован как `"58765:58765"` — сервис доступен в LAN напрямую, как и при локальном запуске (`http://<IP_сервера>:58765/`). Если снаружи должен быть только nginx, замените на `"127.0.0.1:58765:58765"` и поставьте `VECTOR_CALC_TRUST_PROXY: "1"`.
- `memories.sqlite3` создаётся и обновляется прямо в папке проекта: база **вне** образа, переживает перезапуски, пересборки и обновления. Существующий файл используется как есть.
- `models/` тоже на хосте: при первом запуске контейнер скачает туда модель по умолчанию (`VECTOR_CALC_DEFAULT_MODEL`, по умолчанию `en-google` — это долго, прогресс в логах) и повторно скачивать не будет. Остальные модели: `docker compose exec vectorplay python download_model.py --all` (≈3.9 ГБ).
- Контейнер работает не от root. Если папка проекта принадлежит другому пользователю, пересоберите с его id: `VECTORPLAY_UID=$(id -u) VECTORPLAY_GID=$(id -g) docker compose up -d --build`. Крайний случай — раскомментировать `user: "0:0"` в compose.
- Если задать контейнеру `mem_limit` (или `deploy.resources.limits.memory`), приложение увидит cgroup-лимит и само подстроит бюджет кэша моделей.
- Логи: `docker compose logs -f`. Остановка: `docker compose down`. Обновление кода: `docker compose up -d --build`.
- Не запускайте контейнер и локальный `start.sh`/`start.bat` одновременно: оба слушают один и тот же порт.

### Если Docker не создаёт сеть

Ошибка `failed to create network vector-play_default: all predefined address pools have been fully subnetted` означает, что у демона закончились подсети для сетей — обычно потому, что на сервере накопилось много старых compose-проектов. Compose создаёт для проекта отдельную сеть, поэтому ошибка появляется при `docker compose up`:

```bash
docker network ls
docker network prune -f        # удалит сети, к которым не подключены контейнеры
```

Если свободного места всё равно нет, расширьте пул в `/etc/docker/daemon.json` и перезапустите Docker (это перезапустит и остальные контейнеры на сервере):

```json
{
  "default-address-pools": [
    {"base": "10.200.0.0/16", "size": 24},
    {"base": "10.201.0.0/16", "size": 24}
  ]
}
```

```bash
sudo systemctl restart docker
```

Проверьте, что `10.200.0.0/16` не пересекается с вашей LAN (`ip route`).

Если трогать демон нельзя, есть вариант вообще без Docker-сети: в `docker-compose.yml` закомментируйте `ports`, добавьте `network_mode: host` и поставьте `VECTOR_CALC_HOST: 127.0.0.1` — контейнер будет слушать loopback хоста напрямую.

## Безопасность

Сервис рассчитан на работу за nginx — готовый пример с TLS, HTTP/2, HSTS и rate limiting лежит в `deploy/nginx-vectorplay.conf`. Защита на стороне приложения:

- FastAPI + uvicorn: HTTP/1.1 keep-alive, лимит одновременных соединений, `/docs` и заголовок `Server` отключены.
- Строгая валидация каждого запроса (pydantic) и жёсткий лимит тела запроса (16 КБ).
- Rate limiting на IP: 600 запросов/мин на чтение, 30/мин на тяжёлые POST (расчёт и сохранение).
- Не более 4 одновременных расчётов: остальные получают 503 вместо зависания сервера.
- Модель по умолчанию грузится в фоне при старте, остальные — по выбору в интерфейсе; пока модель не готова, API отвечает 503 с `Retry-After`, а не держит соединения (nginx не отдаёт 504).
- Заголовки безопасности на каждом ответе: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store`.
- SQLite: параметризованные запросы, `busy_timeout`, предел коллекции (по умолчанию 50 000 записей, старые вытесняются).
- Контейнер: непривилегированный пользователь, read-only rootfs, `cap_drop: ALL`, `no-new-privileges`, лимит PID, ротация логов.
- Порт по умолчанию открыт в LAN (как и при локальном запуске). Если снаружи должен быть только nginx, публикуйте порт на `127.0.0.1` и включайте `VECTOR_CALC_TRUST_PROXY=1` — тогда мимо TLS и лимитов nginx пройти нельзя.
- Мониторинг: `GET /api/health` (в примере nginx доступен только с localhost).

Важно: `VECTOR_CALC_TRUST_PROXY=1` имеет смысл только если nginx стоит непосредственно перед приложением и **перезаписывает** `X-Forwarded-For` (как в примере), а порт приложения недоступен напрямую. Иначе клиент подделает свой IP и обойдёт лимиты.

## Модерация коллекции

Чтобы коллекцию «Мемориз» можно было показывать детям, каждое сохранение проходит проверку в три слоя (defense in depth):

1. **Словари** (`moderation/*.txt`) — мат и грубые оскорбления блокируются, спорные темы (секс, насилие, оружие, наркотики) отправляются на проверку. Слова хранятся **хешами** (sha256), поэтому мат не лежит в репозитории открытым текстом; лемматизация через pymorphy3 ловит падежи, стемы — производные. Есть allowlist для ложных срабатываний (петух-птица, козёл-животное, сукно).
2. **Векторные эвристики** — на уже посчитанном расчёте: если «плохие» слова лезут в топ ответа, вердикт становится review. Ничего дополнительно не считается, вектора уже в памяти.
3. **LLM** по OpenAI-совместимому протоколу (`/chat/completions`) — смысловая оценка: сексизм, расизм, оскорбительные комбинации. Включается переменной `VECTOR_CALC_LLM_URL`; медленная (секунды), поэтому работает только на сохранении. Поддерживаются «думающие» модели (ответ берётся из `content`, при пустом — из `reasoning_content`).

Режимы (`VECTOR_CALC_MODERATION`): `off` — выключено; `warn` — вердикты считаются и логируются, но публикуются все (для калибровки); `queue` — безопасное публикуется само, спорное уходит в очередь; `strict` — публикация только после ручного одобрения.

Профиль аудитории (`VECTOR_CALC_MODERATION_PROFILE`): `teen` — мягче, **по умолчанию** (до 18 лет): мат уходит на проверку, а не блокируется, «взрослые» слова вроде «оружие»/«секс» сами по себе пример не тормозят, порог срабатывания по соседям выше (4 вместо 2), промпт LLM разрешает грубоватый юмор и сленг. `kids` — строгий (от 7 лет): мат блокируется, спорные слова отправляют пример в очередь, промпт жёстче. Переключение — одной переменной, словари те же.

LLM по умолчанию опрашивается **без «размышлений»** (`VECTOR_CALC_LLM_NO_THINK=1`): ответ ~1 секунда вместо 5–10. Если нужны более вдумчивые вердикты — поставьте `0`.

Что видно в интерфейсе: публичная лента и «свежие мемориз» показывают только одобренное; при сохранении спорного примера появляется «📝 Отправлено на проверку».

Очередь модерации (нужен `VECTOR_CALC_ADMIN_TOKEN`):

```bash
curl -H "X-Admin-Token: ТОКЕН" http://localhost:58765/api/moderation/queue
curl -X POST -H "X-Admin-Token: ТОКЕН" "http://localhost:58765/api/moderation/5?action=approve"
curl -X POST -H "X-Admin-Token: ТОКЕН" "http://localhost:58765/api/moderation/5?action=reject"
```

Проверка произвольного уравнения без сохранения — `POST /api/moderate` (при заданном токене требует его):

```bash
curl -X POST -H "Content-Type: application/json" -H "X-Admin-Token: ТОКЕН" \
  -d '{"terms":[{"text":"король","weight":1},{"text":"мужчина","weight":-1},{"text":"женщина","weight":1}]}' \
  http://localhost:58765/api/moderate
```

Своё слово в список: `python moderation.py --hash "слово"` → добавить строку в `moderation/obscene_ru.txt` (блок) или `sensitive_ru.txt` (проверка). Проверить без сервера: `python moderation.py --check "текст"`, `python moderation.py --llm "уравнение"`, `python moderation.py --mode`.

## Хранение
- `memories.sqlite3` — общая коллекция примеров, остаётся на сервере и **не** публикуется в git. Записи хранятся с привязкой к модели (одинаковое уравнение в разных моделях — разные записи); строки, созданные до появления английских моделей, считаются русскими. В Docker-варианте база монтируется в контейнер напрямую из папки проекта.
- `models/` — архивы моделей и файлы-маркеры `<архив>.ok`, скачиваются отдельной командой и **не** публикуются в git. В Docker-варианте также монтируются с хоста.
- `.venv/` — локальное окружение, **не** публикуется.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_word2vec   # движок и ридеры форматов, модель не нужна
.\.venv\Scripts\python.exe test_ui.py                     # браузерный тест, нужна русская модель
.\.venv\Scripts\python.exe test_memories_ui.py            # коллекция и синхронизация между вкладками
```

Браузерные тесты требуют `playwright` и локальный Chrome, по умолчанию переключают интерфейс на русский и используют модель `ru-rusvectores` (её нужно скачать: `python download_model.py ru-rusvectores`). `test_memories_ui.py` ожидает, что пример «король − мужчина + женщина» уже сохранён в базе, и сохраняет ещё один.

## Примечание
Word2Vec-арифметика не удаляет причинное влияние сущности и не гарантирует содержательных аналогий. Результаты показывают геометрическую близость в пространстве модели.
